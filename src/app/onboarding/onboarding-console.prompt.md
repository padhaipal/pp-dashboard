1.) "use client" component `OnboardingConsole` with two tabs, "Create / update" and "Find". All backend calls use `fetch("/api/proxy/<path>")` (pp-sketch, JSON). Tailwind, zinc/emerald palette matching dashboard/page.tsx and editable-name.tsx.
2.) Exports: `DEFAULT_ROLE_TITLE = { school: "Teacher", block: "BEO", district: "BSA", state: "DGSE", country: "Minister" }`, `normalisePhone(raw)` (strip non-digits; if exactly 10 digits prefix "91"; display-only — the server validates), types `GeoSelection` and `StaffUser`.
3.) Server errors: parse Nest's `{ statusCode, message, error }`; `message` may be a string or string[] — join arrays with "; "; fall back to `HTTP <status>` when the body isn't JSON.
4.) Shared `StaffForm` (used by Create and Edit):
  a.) Full name (required in create mode), WhatsApp number (always required; after the first blur show "Will be saved as <normalised>" under the input, updating live, or "WhatsApp number required" in red when it normalises to empty). Optional `phoneNote` prop renders under the number.
  b.) Geo entity picker: `<select>` of type school|block|district|state|country (default school, no cluster) + search input; debounced 300 ms; once the trimmed query has >= 2 chars call GET geo-entities/search?q=&type=. Rows render `name · type · code · parent_name` (parent_name null → "—") and are clickable. A selection replaces the picker with an emerald chip `name · type · code[ · parent_name]` and a "Clear" button. Results are keyed by `type:query` so stale/other-type results never show; "No matches" only after a fetch for the current key returned empty.
  b2.) Hint text under the "Geo entity" label: an example school in Lucknow, Uttar Pradesh with its nested codes (school 09270904601 · block 092712 · district 0927 · state 09). Hint under "Role": lists DEFAULT_ROLE_TITLE per type and says the title can be overtyped.
  c.) Role input: when a geo entity is selected and the operator has not typed a role by hand (`roleTouched` false), prefill from DEFAULT_ROLE_TITLE[geo.type]. Typing sets roleTouched = true. Edit mode starts with roleTouched = true when the record already has a role_title.
  d.) Notes textarea.
  e.) Submit button disabled until normalised phone is present, plus (create mode) name (trimmed) and a geo selection; also while busy; Edit additionally disables it when nothing changed. `mode` prop ("create" | "update", default create).
5.) Create / update tab. Mode is derived from the WhatsApp number: once the normalised number has >= 10 digits, debounced 300 ms, GET users/lookup?q=<number>; a row whose external_id equals the number exactly (and is a staff role) puts the tab in update mode, else create mode. The lookup is keyed by number so a stale response never applies; while in flight the tab behaves as create. Lookup failure renders "Could not check for an existing user — {message}" under the number.
  a.) Update mode: notice under the number "Existing user: {name} · {role_title} · {geo_entity_name}. Submitting updates this user; blank fields keep their current values." (no prefill), button reads "Update user". Submit PATCHes users/:id with only the non-blank fields (`name`, `new_geo_entity_id`, `new_role_title`, `new_staff_notes`); all blank → "Not updated — fill in at least one field to change" without a request. Success: reset the form and render "Updated. Send this link to {name}:" (name = submitted name, else stored name, else number) with the lookup row's `link` and Copy button. Failure: "Not updated — {server message}".
  b.) Deactivated match (deleted_at non-null): red notice "This number belongs to a deactivated account ({name}) and cannot be updated here. Please contact the next level up the Lifteracy hierarchy about reactivating it." and the submit button is disabled.
  c.) Create mode: POST users/staff-create with `{ name, external_id: normalisePhone(phone), geo_entity_id, role_title?, staff_notes? }` (optional keys only when non-empty after trim). On res.ok read `{ user, link }`, reset the form to empty, and render exactly "Created. Send this link to {name}:" (name = submitted trimmed name) followed by a readonly input holding the link plus a "Copy" button (navigator.clipboard.writeText; label flips to "Copied" for 1.5 s). On failure render exactly "Not created — {server message}". The success panel stays visible after the reset until the next submit.
6.) Find tab: search input, debounced 300 ms, >= 2 chars → GET users/lookup?q=. Defensively drop rows with role dev/admin. Each row: name (or "(no name)") · external_id · role_title · geo_entity_name, plus a "Deactivated" badge when deleted_at is non-null. Clicking a row opens EditPanel (keyed by id so state resets per user).
7.) EditPanel: GET users/:id → `StaffUser & { geo_entity, ancestors }`; prefill the form (geo selection from geo_entity; parent_name = `ancestors[ancestors.length - 1]?.name ?? null` since ancestors are root-first). Roles dev/admin render "Not a staff user." Save PATCHes users/:id with only changed fields: name → `name`, phone → `phone` (normalised), geo → `new_geo_entity_id`, role → `new_role_title`, notes → `new_staff_notes`. Below the form: the link with Copy, then a "Deactivate" button (PATCH { deactivate: true }) when deleted_at is null, else "Reactivate" (PATCH { reactivate: true }). After any successful PATCH show "Saved", refetch the record and bump the Find list so its badge refreshes. Failures render "Not saved — {server message}". "← Back to results" returns to the list.
8.) Lint constraint: never call setState synchronously inside a useEffect body (react-hooks/set-state-in-effect); all state updates happen in timers, promise callbacks or event handlers.
