1.) `PUBLIC_ALLOWED: { pattern: RegExp; methods: string[] }[]` — pp-sketch paths the proxy (route.ts) forwards WITHOUT a session, checked BEFORE `auth()`: `users/:id/public` GET, `users/:id/profile` PATCH, `geo-entities/:id/scores` and `scores.csv` GET, `geo-entities/:id/spotlight` GET, and for the /d student modal `users/:id/literacy-test-scores` GET, `users/:id/usage-history` GET (the Time chart), `users/:id/media` GET, `media-meta-data/:id/audio` GET. Everything else still requires a dev/admin session as before.
1b.) `PUBLIC_MEDIA_RE` — `users/:id/media`: route.ts removes `user.phone` from the JSON unless the caller has a dev/admin session (the admin /user/:id page still needs it).
2.) `isPublicAllowed(path, method)` — exported for tests (Next route files may only export handler names, hence the sibling module).
3.) NEVER add `^users/[^/]+$` (staff detail returns `staff_notes`) or `users/:id/profile` GET. The proxy already passes upstream `Content-Type`, `Content-Disposition` and `Cache-Control` through, so the CSV download and avatar/immutable caching work end to end.
1c.) `forwardedSearch(path, method, search, staff)` — the query string route.ts forwards. `users/:id/media?onboarding=1` makes pp-sketch include the parent-onboarding voice notes (staff `/user/:id` page only); for a non-staff caller the `onboarding` param (`STAFF_ONLY_MEDIA_PARAM`) is removed, every other param and every other path is forwarded untouched. pp-sketch excludes those rows unless the param is present, so the public /d modal can never receive them.

2026-10 (proxy-viewer.ts): a `viewer` param — i.e. a /d page — is forwarded as `x-pp-viewer-id` even for a staff session; the staff header is set only when there is no viewer param (the staff pages). A dev opening an official's link sees exactly what the official sees (students' names / numbers masked unless the viewer is their teacher at a school).
