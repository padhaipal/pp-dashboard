1.) "use client" `MediaTable({ userId, onUserLoaded })` — the staff `/user/[id]` interactions table. Pages `GET /api/proxy/users/:id/media?offset=N&onboarding=1` 100 rows at a time ("Load more"); `onboarding=1` asks pp-sketch for the parent-onboarding voice notes too — the proxy forwards it for staff sessions only. Types and the pure label helpers live in `interaction-rows.ts` (no React).
2.) One row per interaction, newest first, same 10 columns for every kind (Timestamp · Starting State · Student Audio · Transcript · Correct Answer · Answer Status · Score Change · Final State · Level · WPM), `data-kind` on the `<tr>`:
 - **voice** (default; also rows with no `kind` from an older pp-sketch) — unchanged: audio player + duration, STT transcripts with latency and the editable dashboard transcript, displayed answer, Correct/Incorrect, per-letter score changes, states, level (green/red vs the row below — `levelDirection`), wpm.
 - **tap** (comprehension flow answer; `bg-sky-50/60`) — "Flow tap" badge instead of a player; Transcript = `question:` + `chose:` from `row.tap` ("unknown" when the option no longer resolves); Correct Answer = `row.answer` (the correct option's text); Answer Status Correct / Incorrect, or "Not counted" when `answer_correct` is null (a tap the lesson was not waiting for — nothing was recorded); no dashboard-transcript control.
 - **onboarding** (`bg-amber-50/60`) — "Onboarding" badge above the player; Starting State / Final State = the question asked → the next one (`onboardingStateLabel`: "Are you the guardian?", "May we record?", "Child's name?", "Child's age?", "Birth month?", "Onboarding complete"; null question = "Onboarding started"); the three answer columns merge (`colSpan=3`) into `understood:` (`onboardingUnderstood` — Yes / No / Wants more information / Could not understand the reply / the name / "8 years old" / month name / "No name heard" / "No month heard"; "not interpreted" on the first message) and `saved:` (`onboardingSaved` — name / birth year / birth month as held in the onboarding record; the completing turn adds "written to the student's record, with recording permission") plus `lesson 1 started: {word}` on the completing turn (lesson one begins on that same message).
3.) What a turn "saved" is derived server-side (pp-sketch src/onboarding/onboarding-turns.ts) — the classifier's reading of the reply is never stored. Values sit in the onboarding record until the completing turn writes them to the student.
